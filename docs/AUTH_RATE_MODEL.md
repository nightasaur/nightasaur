# 認證請求速率模型（實作前規格）

目的：限制單一後端程序接收的登入／註冊嘗試，保護密碼驗證工作量。不改密碼、不按帳號永久鎖定。

令 W=600 秒。每個 TCP 來源位址最多 60 次/W；每個 (來源位址, trim+lowercase(email)) 組合最多 10 次/W。登入與註冊共用額度，所有獲准嘗試均計數，無論成功或失敗。不存在帳號與存在帳號使用相同算法，不查資料庫。

桶狀態 (n,t_end)：首次獲准請求建立桶；時間 >= t_end 則該桶過期。任一相關桶 n>=上限，回覆 429 並提供 Retry-After，且不增加計數或延長 t_end。否則一次同步操作檢查容量並增加兩桶計數，之後才進入控制器。固定視窗在邊界附近可能容許短時間兩倍額度，這是已知限制。

時間使用單調時鐘，避免系統校時改變期限。鍵用程序隨機金鑰 HMAC-SHA256，不保留原始 IP/email、不寫入日誌或資料庫。最多 10,000 桶；建立新桶前清除過期項，仍無容量則 503 + Retry-After，不繼續密碼驗證。既有桶的請求不因無關新鍵耗盡容量而被拒絕。HMAC 鍵屬暫存識別符，仍按敏感營運資料保護。

信任邊界：以 socket.remoteAddress 為來源，不採信使用者可偽造的 X-Forwarded-For。未提供 socket 位址時拒絕。反向代理後不同用戶可能共享同一個來源額度；正式部署前須測試可信代理拓撲，不能直接啟用 trust proxy=true。

限制：計數不跨程序共享，重啟重設；N 個副本最高可能放大 N 倍。這不是分散式防爆破或 DDoS 防護。正式多副本部署需要經驗證的入口限速或共享原子計數器，以及實際流量校準。IPv6 位址輪換與 NAT 公用來源是後續設計項目。

驗收：前 10 次同組合通過，第 11 次 429；換帳號仍受來源總量限制；封鎖不延長；到期恢復；容量耗盡不放行；偽造 forwarding header 不繞過；429/503 均不呼叫認證控制器。
