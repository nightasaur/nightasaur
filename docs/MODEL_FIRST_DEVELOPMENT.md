# 先建模，再實作：Nightasaur 開源開發規則

本輪既有修復草稿補上模型與驗證對照；後續新功能先完成以下規格再寫程式。這是工程狀態模型，不是千禧年難題的解答，也不是模型訓練或授權審查的替代品。

## 1. 缺資料的表示

每個輸入記為 `(value, source, evidence, assumption)`。未知值以 `UNKNOWN` 表示，不能以零、成功或已授權代替。假設必須能替換，並列出失效時受影響的功能。

授權證據狀態集合為 `E = {UNKNOWN, OBSERVED, REVIEWED, REJECTED}`。找到檔案只能由 UNKNOWN 進入 OBSERVED；REVIEWED 需要對應版本、用途和權利證據。自行撰寫程式不會改變其第三方模型、訓練資料或素材的 E。

待補資料時可以開發介面、演算法、測試替身和模擬器，但模擬結果須標示為合成資料；不得視為真實用戶、模型品質或法律資格。

## 2. 本輪生圖狀態模型

輸入：`K` 為設定的模型識別字串，`P` 為自訂提示或空值，`S` 為 seed。`N` 為本次推論發出的網路請求數。

狀態：DISABLED、READY、RUNNING、COMPLETED、FAILED。

- `K = empty => DISABLED`，且 `N = 0`。HTTP 回應為 503，說明功能未設定。
- `K` 違反專案禁止模型家族政策 => 設定驗證失敗，不得開始推論。
- `K != empty` 僅代表設定就緒，不代表模型權利已審核或品質符合要求。
- `P != empty` 呼叫 `generate_image(P, S)`；否則呼叫 `generate_spirit(name, element, stage)`。方法與參數必須存在。
- COMPLETED 必須由實際服務結果產生；不把未啟用、失敗或模擬圖宣稱為生成成功。

本次明確不提供模型能力等價的自研替代品。移除硬編碼 checkpoint，保留供應商介面供未來有證據的模型接入。完整發行仍需權利審核；設定字串本身不是審核機制。

## 3. 部署啟動的邊界模型

令 `B` 為容器啟動指令，`M(B)` 為該指令直接要求的 schema migration / db push 操作數。要求 `M(B) = 0`：啟動只啟動服務，資料表變更是獨立操作。

這不表示服務永遠不寫資料庫，也不表示所有部署平台設定均已符合要求；只約束本 repository 的 Docker CMD。首次資料表建置必須由另外審核的流程完成，不能靠開機 `db push --accept-data-loss` 補齊。

建置輸入使用 lockfile；Docker context 排除秘密環境檔、資料庫檔、上傳內容、模型權重與根目錄待審圖片。這些排除不會撤回 Git 歷史中已公開的檔案，也不構成完整 SBOM 或資安稽核。

## 4. 模型到測試的對照

| 性質 | 驗證 |
|---|---|
| 空模型 => 503 且零推論連線 | `test_generation_configuration.py`，以會立即失敗的網路替身驗證兩條請求分支 |
| 自訂提示與 seed 傳遞正確 | 同檔案驗證實際存在的服務方法與參數 |
| 啟動不包含 schema mutation | `test_deployment_contract.py` 驗證 JSON CMD 只啟動 Node 服務 |
| 鎖定依賴且不自動執行 install scripts | 同檔案驗證 `npm ci --ignore-scripts` |
| 授權來源未被假設補齊 | provenance inventory 保持未審核狀態；`--check` 驗證來源更新 |

## 5. 後續功能的必要規格

每項功能先列：目標與非目標、輸入及資料來源、未知值與假設、狀態轉移、不可違反的條件、成本/延遲等量化指標、反例與驗收方法。能用簡單決策表表達時不硬套複雜公式。通過測試只證明測試覆蓋的性質；不能聲稱已形式化證明整個產品。
